# Ejercicio 5 · Evaluación de Usabilidad

<div class="not-prose mb-8 flex flex-wrap gap-2">
    <span class="badge-easy">Dificultad: Fácil</span>
    <span class="badge-ce">CE i</span>
    <span class="inline-flex items-center px-2.5 py-0.5 rounded-full text-xs font-medium bg-slate-100 text-slate-700">⏱️ ~45 min</span>
</div>

---

## Objetivo

Realizar una **evaluación de usabilidad** de un compañero/a, identificando problemas y proponiendo mejoras concretas.

---

## Tareas

### Parte A — Preparar el test (5 min)

<div class="not-prose my-6">
<div class="card border-l-4 border-l-brand-500">
<h4 class="font-bold text-slate-900 mb-3">📋 Instrucciones</h4>
<ol class="text-sm text-slate-700 space-y-2 list-decimal list-inside">
<li>Intercambia tu enlace de Figma con un compañero/a (el profesor asignará las parejas).</li>
<li>Antes de evaluar, define <strong>3 tareas</strong> que el usuario debería poder completar en FitTrack:</li>
</ol>
</div>
</div>

| # | Tarea | Pantallas implicadas |
|---|-------|---------------------|
| T1 | "Registra un nuevo entrenamiento de fuerza de 45 minutos" | Dashboard → Nuevo Entrenamiento |
| T2 | "Consulta tu entrenamiento más reciente y revisa los ejercicios" | Entrenamientos → Detalle |
| T3 | "Cambia tu nombre en el perfil" | Dashboard → Perfil |

> Si las pantallas de tu compañero cubren otras secciones, puedes adaptar las tareas.

### Parte B — Evaluación cruzada (25 min)

<div class="not-prose my-6">
<div class="card border-l-4 border-l-emerald-500">
<h4 class="font-bold text-slate-900 mb-3">📋 Instrucciones</h4>
<ol class="text-sm text-slate-700 space-y-2 list-decimal list-inside">
<li>Abre el archivo de Figma de tu compañero/a.</li>
<li><strong>Intenta completar cada tarea</strong> como si fueras un usuario real.</li>
<li>Identifica <strong>mínimo 5 problemas</strong> de usabilidad o diseño.</li>
<li>Documenta cada problema en la tabla siguiente:</li>
</ol>
</div>
</div>

| # | Pantalla | Problema detectado | Severidad (1-4) | Heurística violada | Propuesta de mejora |
|---|---------|-------------------|-----------------|--------------------|--------------------|
| 1 | | | | | |
| 2 | | | | | |
| 3 | | | | | |
| 4 | | | | | |
| 5 | | | | | |

**Escala de severidad** (misma del E1):
- 1 = Cosmético · 2 = Menor · 3 = Mayor · 4 = Catástrofe

### Parte C — Mini checklist de accesibilidad (10 min)

Evalúa el diseño de tu compañero/a con esta checklist rápida:

| # | Criterio | ✅/❌ | Comentario |
|---|---------|-------|-----------|
| 1 | ¿Los textos tienen contraste suficiente (4.5:1)? | | |
| 2 | ¿Los botones tienen tamaño de toque mínimo (44×44px)? | | |
| 3 | ¿Los formularios tienen labels visibles? | | |
| 4 | ¿Los mensajes de error son descriptivos y no solo usan color? | | |
| 5 | ¿Hay jerarquía visual clara (títulos > subtítulos > cuerpo)? | | |

### Parte D — Observaciones generales (5 min)

Escribe **3-5 frases** con:
- Lo que mejor hace el diseño de tu compañero/a
- Lo que más urge mejorar
- Una sugerencia concreta para la siguiente iteración

## Criterios de corrección

| Criterio | Peso | Detalle |
|----------|------|---------|
| **CE i** — Pruebas y documentación de usabilidad | 60% | ¿Los problemas son reales y bien explicados? ¿Las propuestas de mejora son viables? |
| Calidad del análisis | 25% | ¿Los problemas están vinculados a heurísticas? ¿Se valora correctamente la severidad? |
| Checklist de accesibilidad | 15% | ¿Se ha evaluado correctamente cada criterio con evidencia? |
